## 2. 正常链路

| 步骤 | 触发与输入 | 状态及持久输出 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 接入 | 业务经办人上传合成附件，或导入合成模拟待办 | 创建任务和文档版本，机器 `pending`；保存来源、摘要、申请信息和操作记录 | 附件被接收，格式与文件可处理 |
| 2 解析 | 持久任务处理器领取任务 | 机器 `parsing`；产出固定预览、规范化全文、元数据、条款树和同版锚点 | 非空内容，重要证据可核对；不能可靠定位时明确记录限制 |
| 3 审查 | 已解析文档、预置规则、可用 DeepSeek 额度 | 机器 `reviewing`；分别记录规则命中、模型建议、证据和费用；完成后 `completed` | 风险草稿有可复核来源，失败内容不伪装为结论 |
| 4 法务复核 | 法务打开机器草稿及原文 | 法务由 `pending` 到 `in_review`；编辑等级、建议与批注并形成审查版本 | 法务核对证据并确认正式结论 |
| 5 确认与报告 | 法务提交版本和正式结论 | 法务 `confirmed`，记录确认人/时间；Markdown/PDF 分别进入待生成并按同一快照产出 | 业务经办人此时可查看本人正式结论；各格式报告生成成功后才能预览或下载 |
| 6 模拟回写 | 法务选择已确认版本和目标模拟审批单 | 回写 `writing`，本地保存格式化 Markdown 评论；成功 `success` 并返回评论 ID | 评论持久保存；重复请求返回同版已有评论 |

F1 应通过本地上传和模拟待办入口至少各完成一次接入验证；一次真实 DeepSeek 调用贯穿其中一个完整 F1 流程。页面阶段用同一业务链完成 A8，工作台负责把锚点和风险卡片双向联动。

## 3. 三组状态与版本转移

机器、法务、回写是独立维度；任务列表和 API 必须同时给出，不能把机器 `completed` 解释成法务已确认或评论已写回。

列表上的三组当前状态只属于当前文档版本及其当前审查版本。新文档上传后，当前机器、法务、回写分别回到 `pending`、`pending`、`not_written`；旧版已确认快照及报告、回写结果保留为带版本的历史记录。已确认审查再次编辑时，新审查版本进入 `in_review`，其回写为 `not_written`；旧确认版本仍可单独查看。当前版本未确认时不得把旧版等级或回写 `success` 显示为当前结果。业务经办人仍可查看本人历史已确认快照，但必须标明所属文档与审查版本；从未确认过的任务只显示进度与阻塞原因。

| 维度 | 允许转移 | 不允许的捷径 |
| --- | --- | --- |
| 机器 | `pending → parsing → reviewing → completed`；阶段失败 → `blocked`；暂时故障重试回 `parsing` 或 `reviewing` | `blocked` 直接记 `completed`；在不换文件的情况下重试加密/空文/不可辨认扫描件 |
| 法务 | 机器完成后 `pending → in_review → confirmed`；确认后修改创建新审查版本并回到待确认 | 未完成机器草稿直接确认；原位覆盖已确认版本 |
| 回写 | 每个已确认审查版本独立 `not_written → writing → success/failed`；`failed → writing` 重试 | 未确认即写回；把 API 接收或模型完成显示成回写成功 |

报告和模拟评论均引用明确的已确认审查版本。新确认版本建立新的 `not_written` 回写记录，旧评论及失败尝试保留并注明版本。业务经办人可在受阻需换附件或上一文档已确认后上传修订文件，建立新文档版本；处理中的任务不能并行换版。旧文档的审查、报告及回写证据不被覆盖。

## 4. 异常、重试与幂等

| 场景 | 对外可见结果 | 恢复动作 |
| --- | --- | --- |
| 加密 PDF、正文为空、严重模糊扫描件 | 机器 `blocked`，展示具体原因，不产生伪造字段、锚点或风险等级 | 业务重新上传可用附件，形成新文档版本 |
| 解析/OCR 暂时失败，模拟待办附件超时 | 机器 `blocked`，记录阶段、错误、次数及旧证据 | 管理员在条件允许时按原版本重试；处理器从相应阶段恢复 |
| DeepSeek 超时 | 机器 `blocked`，保留规则证据与错误原因 | 暂时故障由管理员按原版本重试 |
| 模型建议无效或缺失 | 规则证据完整时机器草稿可标“需法务补充建议”；证据本身不足则 `blocked` | 法务补充或修订建议并确认；证据不足先修复解析或重新上传 |
| 预计调用成本超过 50 元 | 机器 `blocked/BUDGET_LIMIT`，已解析成果保留 | 用户明确调整预算并记载后，由管理员重试；不得自动追加费用 |
| 服务重启 | 已提交的任务、审查版本、报告与评论仍在；未完成租约可识别 | 启动时恢复可重试任务；已确认和已写回记录不重做 |
| 单格式报告生成失败 | 该确认版本对应格式记为 `failed` 并展示错误；另一格式可独立为 `ready`，法务仍为 `confirmed` | 法务对同一确认版本和格式触发重试；已生成报告不重写，业务仅取 `ready` 产物 |
| 模拟评论首次失败或重复点击 | 回写 `failed` 及原因，或返回已有 `success` 和评论 ID | 法务重试；以 `(任务 ID, 已确认审查版本, 模拟审批单 ID)` 唯一键检查，最多一条同版评论 |

写回以数据库事务保存评论及成功状态；失败尝试和重试时间独立记录。即使重复 HTTP 请求或处理器重启，数据库唯一约束也必须阻止同一键的第二条评论。报告按确认版本和格式保存 `pending/ready/failed`、错误及尝试记录；失败不改变法务确认状态，重试只读取原确认快照，不从当前草稿重建内容。

## 5. 可见性与阶段证据

业务经办人不能读取任何未确认版本的草稿；从未确认过的任务仅见本人进度与阻塞原因，已有旧确认快照时可单独查看该版正式结论及已生成报告。法务能查看原文、机器草稿及审查历史；管理员只按任务处理职责查看状态和故障，不得代审。授权判断要覆盖列表、详情、预览、风险、报告和回写接口，前端隐藏按钮只是辅助。

后端阶段保存 F1–F6 的固定预期标注、请求/响应、状态转移、拒绝访问、失败重试和模拟评论记录。前端阶段补充双向高亮、分页定位、角色页面及目标 Windows 电脑的 A1–A8 全链路证据。技术验证与法务确认、用户阶段验收分别记录；未通过的项目保持未完成状态。
