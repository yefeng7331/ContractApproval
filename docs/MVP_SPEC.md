# 合同审查演示版 MVP SPEC

版本：v1.0（2026-09-23）  
状态：待用户验收；验收后作为首期实施与验收的唯一可执行需求基线。  
来源：[原始需求](../Demand/Demand.md)、[先期 SPEC](../Demand/SPEC.md)及其后的用户确认决定。原文件保留作溯源；若与本文冲突，以用户确认后的本文为准，未确认前不得据此开始开发。

## 1. 目标与阶段

在一台 Windows 电脑上运行中国大陆软件采购合同的**合成数据演示版**：上传或导入模拟待办、解析与定位、企业商业规则及 DeepSeek 辅助审查、法务复核、报告导出、模拟审批评论回写。前后端通过 API 分离，使用一个仓库；不是两套角色客户端。

首期交付按顺序分为两个大阶段：

| 阶段 | 完成条件 |
| --- | --- |
| 后端 | 用 API、F1–F6 固定样例和真实一次 F1 模型调用，证明完整业务链、角色权限、版本、报告、失败恢复与模拟回写；不以临时页面充当验收 |
| 前端 | 接入已验收的 API，完成大盘和双栏工作台；在另一台约 8 GB 内存的 Windows 电脑上运行，完成 A1–A8 的界面与全链路验收 |

两阶段开发前先完成前端设计及接口核对；这不改变“先后端、后前端”的开发和验收顺序。页面行为见[前端设计](FRONTEND_DESIGN.md)，受权限保护的预览及定位数据契约见[后端设计](BACKEND_DESIGN.md)。

真实审批平台、企业单点登录、生产数据保护方案、规则编辑页、批量操作、销售/劳动等其他合同类型及其规则留待后续。首期结果必须明确标为“模拟回写”，不能作为真实审批平台集成的验收证据。

## 2. 角色与可见性

| 本地测试角色 | 首期权限 | 明确禁止 |
| --- | --- | --- |
| 业务经办人 | 上传合成合同、查看本人任务进度；法务确认后查看该版正式结论与建议，报告生成后下载；可查看本人带版本标记的旧确认快照 | 获取任何未确认版本的风险草稿/报告；复核、确认、回写、查看他人任务 |
| 法务审查人 | 查看待复核文档及证据，编辑等级、建议和批注，确认版本，导出报告，触发模拟回写 | 未确认版本回写；无痕修改已确认结论 |
| 系统管理员 | 查看任务状态/阻塞原因/模拟回写结果，触发允许的重试并引导重新上传 | 代法务编辑、确认或回写；首期配置真实平台或发布规则 |

权限由后端逐接口执行。任务从未有确认版本时，业务经办人只能看到进度和可操作的阻塞原因；已有旧确认快照时，该快照可单独查看，但不能泄露当前未确认版本。账号与任务、审查、回写操作须留下操作者和时间记录。

## 3. 输入、证据与审查

- 两个等价入口：本地上传 DOCX、文本 PDF 或清晰扫描件；导入带合成附件与申请信息的模拟审批待办。真实待办监听、拉取及附件下载去重不在首期。
- 附件记录来源、格式、内容摘要、文档版本、提交人和时间。重新上传创建新版本；旧版证据、审查和回写记录仍可追溯。状态与本地文件在重启后保留，只有显式重置才清除演示数据。
- 提取合同标题/编号、送审部门/申请人、双方主体及统一社会信用代码、金额/币种、履行期限、生效条件；缺失或无法识别须标为“未识别”。按原文顺序提取标的、付款、验收、违约、保密、数据安全、知识产权、争议解决等条款；缺失标为“未找到”。
- 每个可定位字段、条款和风险的锚点包含**文档版本、原文片段、规范化全文的零起始 Unicode 字符起止位置（终点不含）、零起始段落索引、预览版本的一起始页码**。DOCX 页码取固定转换预览版；OCR 坐标与识别文本属于同一版本。无法可靠定位时显示原因，不声称精准高亮。
- 风险项区分规则命中、模型判断与法务最终意见，保留规则 ID/版本、条款类型、风险类型/等级、触发原因、原文锚点、依据来源、建议和审查版本。模型生成内容只能作为草稿；缺证据或生成失败时标明原因并转人工，不编造法条、原文或确定性结论。模型依赖超时使机器审查 `blocked`；规则证据完整但建议不可用时，可形成带“需法务补充建议”标记的草稿供人工复核。

首期仅启用以下**企业商业风险演示规则**，均不是普适违法判断：

| ID | 固定样例触发条件 | 预期草稿与建议方向 |
| --- | --- | --- |
| `DEMO-IP-01` | 采购方需要取得或持续使用交付软件，合同却将相关知识产权全部归供应商且未安排满足项目目的的使用权 | 高风险；引用权属/许可原文。建议法务协商权属、许可、源代码交付及第三方权利保证，不预设采购方取得全部著作权 |
| `DEMO-PAY-01` | 到货即付全款，付款前没有可执行的验收条件 | 高风险；引用付款条款并标记验收条款缺失。建议按可核验交付/验收里程碑付款，具体比例由法务决定 |

机器可建议“通过/整改/建议拒绝”；F1 双高风险的机器建议为“建议拒绝并整改”，正式结论由法务确认。综合等级取法务保留风险的最高等级；无已启用规则命中时显示“未发现已启用规则风险”，不自动判“低风险”或“法律安全”；解析受阻时不计算等级。高/中/低三级均可展示，但首期不自动启用其他风险规则或中风险阈值。原需求中的 50%、20% 只是待审示例，不是默认比例或法定阈值。

法律规则只有在中国大陆现行权威来源、适用条件与法务确认均记录后才能作为法律合规判断启用。来源至少记录类型、标题、条款/版本、核查日期、链接、适用条件和确认人；本期候选材料见[先期 SPEC 第 4 节](../Demand/SPEC.md)，均待复核。真实主体经营异常查询不在首期；只能使用明确标注的合成状态。

## 4. 三组状态、报告和回写

| 维度 | 状态 | 约束 |
| --- | --- | --- |
| 机器审查 | `pending → parsing → reviewing → completed`；失败为 `blocked` | `completed` 仅表示草稿完成。加密、空文、严重模糊、解析失败、依赖超时或预算阻塞须记录原因和可恢复动作；重试次数与旧证据保留 |
| 法务复核 | `pending → in_review → confirmed` | 机器完成后才能复核；确认记账号、时间、版本；改动已确认内容须形成新审查版本并再次确认 |
| 模拟回写 | `not_written → writing → success/failed` | 仅对已确认审查版本触发；失败可重试。同一任务、确认版本和模拟审批单 ID 的评论最多一条，新确认版本可形成新评论 |

大盘的三组**当前状态**均指向当前文档版本及其当前审查版本：新文档上传后机器回到 `pending`、法务回到 `pending`、回写显示 `not_written`；已确认内容再次修改产生新审查草稿，法务回到 `in_review`，该草稿的回写显示 `not_written`。旧确认版本、报告和回写状态作为历史记录保留。业务经办人可查看本人旧版已确认结果，但必须清楚标出所属文档及审查版本，不能与当前未确认内容混合；从未有确认版本时仍只见进度与阻塞原因。

法务确认后，为同一确认快照生成 Markdown 和 PDF 报告；每种格式独立标记待生成、已生成或失败。生成失败不撤销法务确认，可由法务对同版重试；业务经办人只能下载本人已确认且已生成的报告。报告含合同标题/编号、送审部门/申请人、相对方、金额与履行期限、综合等级与正式结论、逐项证据定位/原因/依据/最终建议、法务批注、确认人/时间/版本与“模拟回写”标识。未核准法律依据标“待法务核定”。模拟评论为 Markdown，含风险总评、重点事项、法务批注、确认版本及演示标识。

## 5. 界面与技术约束

- 大盘展示合同名称、申请人、业务类型、金额、机器/法务/回写状态、综合风险等级、创建时间；支持状态/风险筛选及上传。未确认结果对业务经办人隐藏。
- 工作台左侧为分页合同原文及元数据高亮，右侧为分级风险卡片、依据、条款差异、建议一键复制及法务采纳/编辑；采纳计入审查版本。点击任一侧都能定位并选中另一侧对应内容。法务区提供批注、确认、模拟回写状态轮询和报告预览。阻塞告警在首期以大盘状态提示呈现，外部通知后置。
- 前端采用 React、TypeScript、Vite、PDF.js；后端采用 FastAPI、Python、SQLite 和本地文件，单服务持久任务队列；最终演示提供一个启动脚本启动所需本地服务。DOCX 固定预览候选为 LibreOffice，文本 PDF 抽取候选为 pdfplumber，扫描件 OCR 候选为 PaddleOCR CPU。以固定样例验证可行性，不能把候选组件当成已验证能力。
- DeepSeek API 用于合成合同的辅助建议；演示总预算为 **50 元人民币**。调用前按预计最大费用预留额度，预计超过上限时阻止新调用、保留任务并标记预算受阻，只有用户明确调整预算才继续。应用内费用为估算，准确费用以供应商账单为准；模型 ID、单价和汇率需在实施前核对并记录。真实合同上传外部模型的政策另行决定。
- 目标机为另一台约 8 GB 内存、可安装依赖、无独立 GPU 假设的 Windows 电脑；在该机验证 API 直连、CPU OCR 与完整演示。

## 6. 固定样例与验收

样例均为合成数据。每份样例要有可复核的预期字段、条款、页码、段落、字符位置、风险项、等级和建议清单；逐项全通过才算达标。

| 样例 | 内容 | 必须证明 |
| --- | --- | --- |
| F1 | DOCX 软件采购合同，含两条演示风险 | 元数据、两项高风险、证据锚点、法务编辑、真实一次 DeepSeek 调用、模拟回写 |
| F2 | 与 F1 同语义但排版分页不同的文本 PDF | 风险一致，页码和高亮属于 F2 本版 |
| F3 | 与 F1 同语义的清晰合成扫描件 | CPU OCR、条款与锚点可人工核对，风险一致 |
| F4 | 已补足使用权与验收后分期付款的合同 | 两条规则不误报；无其他命中时显示“未发现已启用规则风险” |
| F5 | 加密 PDF、空文、严重模糊扫描件各一份 | 各自 `blocked`，原因明确，可重新上传，无虚假结论 |
| F6 | 模拟待办超时、首次模拟回写失败及重复提交 | 正确失败/重试状态；同版评论最多一条 |

| 验收 | 后端阶段证据 | 前端阶段补充证据 |
| --- | --- | --- |
| A1 接入解析 | F1–F3 上传、模拟待办导入 F1，字段和条款逐项匹配 | 上传及导入操作可用 |
| A2 定位联动 | F1–F3 风险锚点的版本、页、段、字符位置逐项匹配 | 原文与卡片双向高亮、跳页准确 |
| A3 风险建议 | F1–F3 两条高风险和依据，F4 不误报，法务编辑留版本 | 卡片展示和编辑可用 |
| A4 复核权限 | 逐接口验证确认前隔离、法务确认、管理员拒绝 | 页面按角色隐藏并阻止越权操作 |
| A5 结论报告 | 已确认 Markdown/PDF 同版同内容；单格式生成失败可在同版重试且不回退确认，业务仅取本人已生成版本 | 预览与下载可用，失败/恢复状态可见 |
| A6 模拟回写 | 确认前拒绝，成功留评论 ID，失败可重试且去重 | 明示模拟、展示结果及失败原因 |
| A7 受阻重试 | F5/F6 原因、重试、新旧证据与重启恢复可复查 | 大盘/工作台可查看及执行允许的恢复动作 |
| A8 端到端 | F1 API 完整链路和操作记录 | F1 页面完整链路，目标 Windows 电脑可运行 |

受控模型响应可验证固定样例链路，但必须另外完成一次 F1 真实模型调用。技术 A1–A8 通过、法务对规则与示范条款确认、用户对阶段成果验收是三件分别记录的事。
