# 后端剩余八个工作块执行清单

更新日期：2026-09-24。用途：供后续任务窗口规划和逐功能执行；**本文件是工作清单，不是新的需求或验收基线**。产品范围与验收以 [MVP SPEC](MVP_SPEC.md) 为准，状态与证据以 [实施状态](IMPLEMENTATION_STATUS.md) 为准；实现细节分别查阅 [核心流程](CORE_FLOW.md)、[后端设计](BACKEND_DESIGN.md)、[前端设计](FRONTEND_DESIGN.md)及[已确认决策](DECISIONS.md)。开始每项工作前重新核对这些文件和当前工作区，不能仅凭本清单的日期判断进度。

## 起点与执行规则

- 当前已有账号与权限、接入和换版、持久解析作业、DOCX 基础提取、法务读取解析结果、即时规则草稿 API。用户已验收“同版固定规则草稿持久化”；“固定规则草稿缺陷修复与证据校验”仍为 `PENDING_ACCEPTANCE`，其行为变更部分不因原组件验收自动转为通过。后续状态以 `docs/IMPLEMENTATION_STATUS.md` 为准。
- 八块是**规划粒度**，不是八次不可拆分的交付。每块可拆为可独立验证的小功能；每完成一个小功能，新增或更新独立冒烟测试，覆盖主要成功路径和关键失败或权限路径，运行并记录命令、结果、模拟前置条件；同步更新 `docs/IMPLEMENTATION_STATUS.md` 的证据与验收状态及 `README.md` 的实际可用步骤。接口、流程或已确认决策变化时更新相应设计文档。
- 每次报告按“业务要求 → 实现位置 → 验证证据 → 未验证/受阻 → 待用户验收”给出；技术测试通过后停在 `PENDING_ACCEPTANCE`，等用户明确验收再进入下一项。法务签批、用户验收和技术验证分别记录。遵守 `AGENTS.md` 的操作红线及当前授权范围。
- 可提前准备样例和接口契约；DOCX、文本 PDF、OCR 可在统一锚点契约后分项开发；报告与模拟回写可在确认快照契约稳定后分项开发。集成验收必须等实际链路完成。并行准备不跳过逐功能验收停点。

## 1. 固定样例与预期标注

**交付**：建立 F1–F6 合成文件或故障场景及可复核的答案清单。对可解析文件标注适用的字段、条款、版本、页码、段落、字符区间、风险、等级和建议；对故障场景标注预期状态与恢复动作。F5 覆盖加密 PDF、空文、严重模糊扫描件，F6 覆盖模拟待办超时和回写失败/重复提交。F1/F4 已有固定 DOCX 与预览前答案清单，但页码、区域及全链路证据尚缺，不直接计作正式 F1/F4 整体验收。

**完成证据**：样例与答案清单可单独读取；核对样例确为合成数据，F1/F4 的规则预期与当前已启用规则一致。后续每块用同一批标注做逐项对照，只有对应能力实际完成后才记录该场景通过。依据：[MVP SPEC 第 6 节](MVP_SPEC.md#6-固定样例与验收)。

## 2. 三类文档解析、固定预览与定位

**交付**：DOCX 固定 PDF 预览和本版页码/区域映射；文本 PDF 提取；扫描件 CPU OCR；受保护的同版预览 API。字段、条款和风险锚点引用同版规范化全文及预览。候选组件 LibreOffice、pdfplumber、PaddleOCR CPU 均须用固定样例验证，未验证前保持候选状态。

**完成证据**：F1–F3 的正文、字段、条款、页码和可定位区域逐项匹配标注；F2 不复用 F1 页码；F3 OCR 文字与坐标人工可核对；无法可靠定位时返回原因并关闭精准高亮。F5 三类异常进入正确的 `blocked` 状态与恢复路径；预览接口验证版本和三角色权限。依据：[后端设计第 1、3 节](BACKEND_DESIGN.md)。

## 3. 自动审查作业与持久机器结果

**前置**：当前待验收的规则证据校验及手动同版草稿持久化得到用户验收；解析证据契约稳定。

**交付**：把同版规则判定接入服务内持久审查作业，分别保存规则来源、证据、审查阶段状态和尝试记录；提供可读取的持久机器草稿，区别于现有 `persisted=false` 即时 `/risks` 响应。完成、受阻、重试、租约恢复和错版拒绝遵守 [核心流程](CORE_FLOW.md) 与 [后端设计](BACKEND_DESIGN.md)。

**完成证据**：F1 两条风险与同版原文对应，F4 不误报；重启、重复领取、来源证据变化、坏证据和越权请求不能产生错版或重复结论。机器完成状态只在需要的审查环节完成后出现，不能把规则草稿当成法务确认结果。

## 4. DeepSeek 辅助建议与预算

**前置**：机器审查结果能保存规则证据，且可区分规则与模型输出。

**交付**：核实并记录实施时的模型 ID、官方计费、汇率和账号条件；按 [MVP SPEC 第 5 节](MVP_SPEC.md#5-界面与技术约束)实现 50 元人民币演示预算的调用前预留、超额阻止、用量与估算账本、超时或未知用量处理。模型只用于合成合同；真实 F1 调用在取得该付费调用所需的明确授权后执行。

**完成证据**：受控响应覆盖正常、超时、无效内容、预算不足及恢复；规则证据与模型建议分别保存，模型不能制造原文锚点；另留一次真实 F1 调用及供应商账单核对状态。应用估算不写成供应商实际收费或精确上限。

## 5. 法务复核、确认与版本权限

**前置**：机器结果可按文档版本读取，证据足以供法务复核。

**交付**：法务采纳或编辑等级、建议和批注，按基础版本生成复核版本并确认正式结论；确认后修改生成新版本，旧确认快照保留。落实确认前隔离、本人业务仅见已确认版本、管理员不得代审、版本冲突拒绝和操作记录。

**完成证据**：F1 法务修改、确认、再编辑及换附件后，当前三组状态与旧版确认结果严格分离；逐接口覆盖未登录、本人业务、其他业务、法务、管理员及过期基础版本。机器未完成或证据不可核对时不得确认。依据：[后端设计第 2、3 节](BACKEND_DESIGN.md)。

## 6. 同版 Markdown/PDF 报告

**前置**：法务确认快照及版本权限已稳定。

**交付**：确认时为 Markdown、PDF 各自登记生成任务；按同一确认快照生成、保存状态并提供受保护的状态与文件接口。单格式失败由法务按原确认版本重试；报告失败不回退法务确认。

**完成证据**：两格式内容与同版正式结论一致；`pending/failed` 文件请求不返回空文件；业务仅能取得本人已确认且 `ready` 的版本；单格式失败、重试、重启和新审查版本均不覆盖旧报告。依据：[MVP SPEC A5](MVP_SPEC.md#6-固定样例与验收)。

## 7. 模拟审批评论回写

**前置**：法务确认版本及目标模拟审批单已明确；可与第 6 块在稳定的确认快照契约后分别开发。

**交付**：仅对已确认版本写入本地模拟评论，保存回写状态、评论 ID、失败原因和尝试；使用 `(task_id, confirmed_review_version, mock_approval_id)` 唯一键确保重复请求和重启后的幂等性。

**完成证据**：确认前拒绝；F6 首次失败后可重试；重复提交最多一条同版评论并返回已有 ID；新确认版本有独立状态，旧评论保留且清楚标明“模拟回写”。依据：[核心流程第 4 节](CORE_FLOW.md)。

## 8. 后端阶段集成验收

**前置**：第 1–7 块所需能力已各自完成技术验证及用户逐功能验收。

**交付**：在实际后端 API 上用 F1–F6 对照答案清单，逐项记录 [MVP SPEC A1–A8 的后端列](MVP_SPEC.md#6-固定样例与验收)：接入与解析、证据定位、风险与法务编辑、角色权限、同版报告、模拟回写、失败恢复、F1 完整链路。记录请求/响应、版本和状态转移、重启恢复、运行电脑及依赖版本、真实模型调用、应用估算及账单核对状态。

**完成证据**：每项标记 `PASS`、`FAIL`、`BLOCKED` 或 `UNVERIFIED` 并链接对应证据；缺项保持未完成。后端 API 阶段通过后仍需用户明确验收；法务对规则与示范条款的确认另行记录。前端双向联动和另一台 Windows 电脑的完整演示属于前端阶段。
