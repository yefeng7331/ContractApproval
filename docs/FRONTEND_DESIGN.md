# 前端设计与交互契约

状态：待用户验收；设计文档，尚无前端实现。产品范围及 A1–A8 以 [MVP SPEC](MVP_SPEC.md) 为准，接口与权限以 [后端设计](BACKEND_DESIGN.md) 为准，状态转移以 [核心流程](CORE_FLOW.md) 为准。本文件只细化首期浏览器界面；先完成设计，开发仍按后端、前端两个阶段推进。

## 1. 客户端边界与页面

单一 React + TypeScript + Vite 浏览器客户端供三个本地测试角色使用，文档预览使用 PDF.js。首期面向 Windows 桌面浏览器；三角色共用页面与组件，登录后按服务端角色呈现允许的操作。界面隐藏不构成授权，所有数据与动作仍由后端逐接口校验。真实审批平台、规则编辑页、批量操作、外部通知及移动端适配不属于首期验收。

| 页面/区域 | 首期内容与动作 | 数据及角色边界 |
| --- | --- | --- |
| 登录 | 输入本地测试账号；失败与会话失效给出提示；退出清除当前界面数据，刷新后重新登录 | `POST /sessions`、`DELETE /sessions/current`；以服务端角色决定可见操作 |
| 大盘 | 合同名称、申请人、业务类型、金额、创建时间、当前文档的机器/法务/回写三组状态及当前正式综合等级；状态/风险筛选，打开任务 | `GET /tasks`；业务只见本人任务，当前版本未确认时等级为空；旧确认结论另标版本，管理员只见职责范围的状态与故障 |
| 接入 | 上传合成 DOCX/PDF/扫描件或选择固定模拟待办；提交后显示异步进度 | `POST /tasks`、`GET /mock-pending`、`POST /mock-pending/{id}/import`；仅业务经办人；模拟入口标“模拟待办” |
| 工作台左栏 | 同版 PDF 分页预览、页码跳转、合同字段与条款、元数据及风险高亮；点击高亮选中右侧卡片 | `GET /tasks/{task_id}/document` 与 `/document/preview`；法务可看草稿，业务仅看本人已确认版本，管理员不可看原文 |
| 工作台右栏 | 综合摘要、分级风险卡片、原文摘录、规则与依据、条款差异、建议复制；点击卡片跳到左栏 | `GET /tasks/{task_id}/risks`；区分规则、模型与法务意见；未核定依据标“待法务核定” |
| 法务操作 | 采纳或修改等级、建议和批注，确认审查版本；显示确认人、时间和版本 | `PUT /tasks/{task_id}/review`、`POST /tasks/{task_id}/confirm`；仅法务，机器完成且证据可核对才可确认 |
| 报告与模拟回写 | 已确认 Markdown/PDF 分别显示待生成、已生成或失败；已生成可预览/下载，法务可重试失败格式；法务触发模拟回写并查看状态、评论 ID、失败原因和重试 | `GET /tasks/{task_id}/reports/status`、`GET /tasks/{task_id}/reports/{format}`、`POST /tasks/{task_id}/reports/{format}/retry`、`POST/GET /tasks/{task_id}/mock-writeback`；业务仅取本人已确认且已生成的报告；明确标“模拟回写” |
| 受阻恢复 | 展示阻塞阶段、原因、尝试次数及恢复指引；受阻需换附件或上一文档已确认后，业务可上传修订版；暂时故障由管理员重试 | `GET /tasks/{task_id}`、`POST /tasks/{task_id}/documents`（提交 `base_document_version` 与附件）、`POST /tasks/{task_id}/retry`；依服务端状态和角色显示动作 |

大盘和工作台分别显示机器、法务、回写三组状态，不能压成一个“已完成”标签。无已启用规则命中时显示“未发现已启用规则风险”，不显示“法律安全”。受阻任务不显示虚构的等级、建议或定位高亮。

v0.4 仪表盘以当前角色可见的任务为统计范围，按当前文档的主处理阶段互斥归入“处理受阻、机器处理中、待法务复核、法务已确认”；受阻优先归类，避免同一任务重复计数。概览显示各阶段份数与占比，并突出当前角色可以处理的下一步；合同明细继续分别展示机器、法务和模拟回写状态。概览按未筛选的可见任务计算，列表的状态与风险筛选不改变概览口径。旧版已确认结果只在对应版本的历史信息中呈现，不计入当前分布；当前版未确认时不显示正式综合等级。

## 2. 页面行为与版本约束

1. 上传或模拟导入返回 `task_id` 后打开任务；HTTP 接收成功只表示任务已创建，不能显示为审查完成。模拟导入在附件处理阶段超时，仍保留任务及受阻状态。
2. 工作台以 `task_id + document_version + review_version` 识别当前视图。文档与预览带 `document_version`，风险另带可选 `review_version`，报告状态/文件带必填确认 `review_version`；预览、字段、风险、编辑与报告必须属于相应版本。切换任务或文档版本时清除旧高亮和选中项，旧请求结果不得覆盖新视图。大盘三组当前状态只属于当前文档/审查版本：新文档为 `pending/pending/not_written`，已确认结论再编辑的新草稿为法务 `in_review`、回写 `not_written`。业务经办人只使用任务摘要给出的最新已确认版本对查看历史正式结果，不能混入更新的未确认草稿；旧正式结论和旧回写结果须标明所属版本，当前未确认版本的等级保持空值。
3. PDF.js 展示后端固定 PDF 预览：DOCX 使用本版转换文件，文本 PDF 使用本版原件，扫描件使用 OCR 对应的本版预览。可定位字段、条款和风险按锚点中的页码与页面区域绘制高亮。点击风险卡片滚动至首个区域并选中全部区域；点击风险高亮选中对应卡片；多页锚点可有多个区域。前端不重新猜测位置或套用其他样例的页码。
4. `locatable=false`、页面区域缺失或版本不匹配时，不绘制“精准定位”高亮；显示原文摘录、可靠的页/段信息和不能定位的原因，交由法务核对。可定位锚点若与预览不吻合，A2 不通过。
5. 条款差异比较原文摘录与建议条款文本；只有说明性建议时显示建议正文，不伪造替换条款。复制不改变审查版本；法务采纳或编辑通过 `PUT /review` 提交基础审查版本。已确认内容再次修改产生新草稿，新版重新确认前不能生成其报告或回写。
6. 从未确认过的任务，业务视图只显示本人进度、阻塞原因和允许的重新上传动作；不请求或展示草稿、原文预览、建议、等级及报告。存在旧确认快照时，业务可单独查看本人旧版正式结果，但当前未确认内容仍不可见。管理员只见任务状态、故障及允许的重试/模拟回写结果，不进入原文或法务编辑区。直接访问页面链接也遵循相同限制。
7. 报告状态、预览和下载始终指定确认版本；Markdown/PDF 独立显示 `pending/ready/failed`，仅 `ready` 可打开，失败时仅法务见错误和同版重试入口，业务只见暂不可用提示。两格式对应同一确认快照，报告失败不改变“法务已确认”。回写按钮显示目标模拟审批单及确认版本。请求中禁用重复点击；失败可对同一键重试，成功显示已有评论 ID，不能因重复点击产生第二条同版评论。

## 3. API 对接、异步状态与错误反馈

所有业务请求使用 `/api/v1` 和 `Authorization: Bearer <token>`。登录返回的不透明令牌只保存在浏览器内存，不写入 Cookie、`localStorage` 或 `sessionStorage`；刷新页面即清除令牌并回登录页，退出时调用服务端撤销接口。预览 PDF 和报告通过带 Bearer 凭据的请求取得数据，再交给 PDF.js 或下载/预览组件，不使用公开静态路径；切换任务或退出时释放上一份预览数据。客户端不持久化合同正文、风险草稿或报告文件。

任务处于 `pending/parsing/reviewing` 或回写为 `writing` 时读取对应状态并展示进度；进入终态、离开页面或会话失效后停止轮询。列表筛选以服务端返回的可见数据为准。法务编辑期间提示未提交内容，提交中禁用重复确认和回写；版本冲突后重新读取当前版本，由法务核对修改，不能自动覆盖。

| 服务端结果 | 页面处理 |
| --- | --- |
| 401 | 清除受保护视图和预览，返回登录，停止轮询 |
| 403 | 显示无权访问/操作，不展示缓存内容；隐藏按钮仅为辅助 |
| 404 | 显示任务或版本不存在，提供返回大盘入口 |
| 409 | 提示状态或版本变化，重新读取并要求法务核对后再提交；未确认报告/回写不可继续 |
| 409/`REPORT_NOT_READY` | 对已确认但仍在生成或生成失败的格式显示暂不可用；法务按报告状态查看错误并仅对失败格式重试，业务不能重试 |
| 422 | 展示附件或输入无法受理的原因，允许修正后重新提交；不显示为异步 `blocked` |
| 异步 `blocked` | 展示阶段、原因、尝试次数及后端恢复类型；新附件由本人业务账号重新上传，暂时故障由管理员重试，预算阻塞等待用户明确调整预算 |
| 模拟回写 `failed` | 保留确认版本、错误和尝试记录；法务可用同一确认版本与模拟审批单重试 |

界面文案区分“机器草稿完成”“法务已确认”“模拟回写成功”。模型建议无效但规则证据完整时，法务可见“需法务补充建议”；证据不足按 `blocked` 处理。未获法务核定的法律依据不作为正式法律结论展示。

## 4. 前端阶段验收映射

后端先以 API 和 F1–F6 完成其阶段证据：F1 为 DOCX，F2 为不同分页的文本 PDF，F3 为扫描件，F4 为修正风险后的合同，F5 为三类受阻附件，F6 为模拟待办超时及回写失败/重试。以下仅列前端补充的可观察结果。每项都在实际后端 API 上验证，模拟数据与真实平台能力分开记录。

| 验收 | 前端操作及通过条件 |
| --- | --- |
| A1 | 业务账号可上传 F1–F3 创建任务、从模拟待办导入 F1，并查看处理状态；法务在机器完成后可于工作台核对本版字段与条款；提交后不提前宣称完成 |
| A2 | F1–F3 分别用本版预览验证卡片点原文、原文高亮点卡片；页码、区域和选中项与固定标注一致；不能定位的项明示限制 |
| A3 | F1–F3 展示两项高风险、原文和建议，F4 无误报；法务采纳/编辑后可见新版本且与机器内容区分 |
| A4 | 业务从未确认的任务看不到草稿、预览和报告；新版本待审时只可见标明版本的旧确认快照，不见新草稿或当前风险等级；法务可编辑确认；管理员无代审/回写入口；直接请求仍由后端拒绝 |
| A5 | 法务确认后，同版 Markdown/PDF 各自显示生成状态，`ready` 可预览、下载；单格式失败由法务同版重试且确认状态不回退，业务仅得本人已生成报告 |
| A6 | 未确认无回写入口；确认后标“模拟回写”，显示写入、失败、重试、成功和评论 ID；重复提交仍对应同版同一评论 |
| A7 | F5/F6 显示阻塞/失败原因及正确角色的恢复动作；重新上传或重试后状态更新，法务可追溯旧版证据 |
| A8 | F1 在另一台约 8 GB 内存 Windows 电脑走通接入、解析、法务修改确认、报告和模拟回写；记录浏览器、运行环境及实际 API/模型证据 |

首期视觉验收以信息清晰、分页预览可核对、角色与状态不误导为准。候选解析组件、目标机兼容性、真实模型调用和真实平台接口均以实际验证或资料确认记录；本设计文档不等于能力已实现。
